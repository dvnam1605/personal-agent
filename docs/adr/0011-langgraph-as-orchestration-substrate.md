# ADR 0011: LangGraph as Orchestration Substrate, Not Orchestration Policy

- **Status**: Approved
- **Date**: 2026-08-18
- **Supersedes**: None. Clarifies the "Core orchestration: LangGraph" declaration in `MASTER_PLAN.md` and constrains the implementation of ADR 0002, ADR 0004, ADR 0009, and ADR 0010. Where ADR 0010 states "Redis/PostgreSQL checkpoints", this ADR narrows the checkpoint store to PostgreSQL; Redis retains only cache, rate-limit, and short-term history roles.
- **Context**:
  `MASTER_PLAN.md` names LangGraph as the core orchestration runtime, but P0–P3 shipped with no LangChain dependency and with hand-written substitutes for several LangGraph primitives (`ExecutionPlan.topological_order()`, `assistant_runs.state_snapshot` checkpointing, `trace_span()`). Left unresolved until P16, this ambiguity would produce two competing state layers and would break the durable pause/resume requirement in P18-03. A decision is also needed on the prebuilt `langgraph-supervisor` package, which a future implementer would otherwise reach for when building P16.
- **Decision**:
  1. Adopt LangGraph as the **execution substrate**: `StateGraph` for graph topology, the `Send` API for dynamic fan-out, `interrupt()` for human-in-the-loop pauses, and an official checkpointer for durable resumability.
  2. Retain all **orchestration policy** as first-party code: `FastTriage`, `RouteDecision`, Supervisor structured planning, DAG validation, `CapabilityGate`, `LatencyBudgetManager`, and bounded ReAct stop logic. No prebuilt agent loop may own these decisions.
  3. **Reject** `langgraph-supervisor` / `create_supervisor`. It is no longer actively maintained upstream, and its message-history handoff model conflicts with three approved invariants: structured `ExecutionPlan` DAGs (P16-01, P16-03), mandatory parallel execution of independent specialists (MASTER_PLAN §13, P16-04), and the peer-to-peer prohibition in ADR 0009 — a handoff transfers control between agents, which is precisely what ADR 0009 forbids.
  4. Reject the tool-wrapped subagent pattern as the Supervisor mechanism for the same reason: it cannot express task dependencies or guarantee parallel scheduling. It remains acceptable only for a specialist that composes deterministic tools.
  5. Assign two distinct persistence roles. The LangGraph checkpointer owns **resumability** (thread state, interrupt survival, replay). The P3 tables `assistant_runs`, `tool_executions`, `llm_executions`, and `audit_events` own **observability, audit, and budget accounting**. Neither may be derived from the other, and `assistant_runs.state_snapshot` remains a sanitized read-only projection.
  6. Declare the substrate dependencies at P3 so the resolved versions are locked and reviewable before any orchestration code exists: `langgraph`, `langgraph-checkpoint-postgres`, `langsmith`, and `psycopg[binary]`. Declaration is not usage — P4–P10 must contain no `langgraph` import, and P11 is the first phase permitted to import it.
  7. Accept two PostgreSQL drivers. The data layer keeps asyncpg via SQLAlchemy; the checkpointer requires psycopg3. `psycopg[binary]` is mandatory so libpq ships with the wheel rather than being a system prerequisite. Do not migrate the data layer to psycopg, and do not write a bespoke checkpointer over asyncpg to avoid the second driver.
- **Consequences**:
  - Positive: The project inherits durable checkpointing, interrupt/resume, streaming, and LangSmith integration — the parts that are hard to implement correctly — while keeping every architecture invariant enforceable in reviewable first-party code.
  - Positive: P18 approval pause/resume gains a proven durable mechanism instead of a bespoke one.
  - Negative: Couples the runtime to LangGraph's `StateGraph` and checkpointer APIs, which have historically introduced breaking changes across minor versions. Mitigated by confining LangGraph usage to `app/harness/` and keeping `app/domain/` free of framework imports.
  - Negative: Two persistence layers must be kept conceptually distinct, requiring reviewer attention at P11 and P18.
  - Negative: `AssistantState` is a Pydantic model with `validate_assignment=True`; adapting it to LangGraph reducer semantics requires an explicit channel design at P11 rather than passing the model through unchanged.
  - Negative: Two PostgreSQL drivers ship in the runtime image (asyncpg + psycopg3), increasing install size and giving two connection-pool configurations to tune. Accepted as cheaper than maintaining a bespoke checkpointer.
  - Negative: Declaring dependencies at P3 pulled `langchain-core`, `langgraph-prebuilt`, and `langgraph-sdk` into the lock file, and resolution pinned `websockets` down from 17.0.1 to 15.0.1 via `langgraph-sdk`. `uvicorn[standard]` also consumes `websockets`, so the WebSocket path must be re-verified if it is ever used.
